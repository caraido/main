# `analysis/` — promoted analyses

Stage 2 of the analysis lifecycle:

```
tests/   ->   analysis/   ->   figures_for_paper/
pilot         promoted          published
                  |
                  +-> _archive/     (piloted, did not pan out)
```

Code arrives here once it is worth depending on, and is expected to keep working.
**Several modules here are load-bearing for paper figures despite not living in
`figures_for_paper/`** — check the status column before moving, renaming, or
deleting anything.

**library** — imported by other code; changing its API breaks callers.
**pipeline** — regenerates the source data a published figure is built from.
**supplementary** — a finished analysis that supports the paper without a figure of its own.

### Two modules that look archivable and are not

`cross_task_regression.py` and `helpers/_cross_patient_helpers.py` were both
classified as dead during the 2026-07 reorganization and both turned out to be
libraries. `cross_task_regression` supplies the peak-bin helpers that
`predict_io` uses to write `trial_predictions_*.csv`, which two paper figures
depend on; archiving it would have broken them silently, since the failure only
appears when a figure is *regenerated*. `_cross_patient_helpers` supplies 19
functions to `cross_task_transfer` even though the four CLIs that shipped
alongside it are dead. `helpers/_phoneme_semantic_helpers.py` is likewise shared
far beyond its namesake suite.

The lesson worth keeping: in this repo, "which folder is it in" and "how old is
it" are both poor proxies for whether something matters. Grep for importers.

### `cross_task_transfer` — the one supplementary analysis

Complete, re-run 2026-07-28 at 7 participants (CP added to the auditory cohort; **CP was
retired 2026-08-12**, so consumers now read 9 — see entry 015;
the same run also fixed the channel-pairing defect described in
`cross_task_regression._resolve_to_electrode_names`), results in
`results/cross_task_transfer/`. It is the negative control behind the paper's
framing — naive picture↔auditory transfer is at chance, which is what motivates
the co-training result. It has no panel in `figures_for_paper/` and may deserve
one; that is a scientific decision, not a cleanup one.

## Conventions

- **Output** goes to `results/<analysis>/` via `utils.paths.results_dir("<analysis>")`.
  Never compose a results root by hand — three competing roots is how one
  analysis suite ended up split across two directories, half of it outside the
  repository. See [`utils/paths.py`](../utils/paths.py).
- **Run** as `python -m analysis.<topic>.<name>` from `main/`, in the `Speech`
  conda env (the project pickles need `dill`).
- **Which result runs are safe to touch** is recorded in
  [`docs/results_index.md`](../docs/results_index.md), regenerated by
  `python -m utils.audit_runs --write`. Runs marked `PINNED` are named in
  tracked source and must not be deleted.
