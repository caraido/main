# Pinned and superseded result runs

Generated by `python -m utils.audit_runs --write`. Do not hand-edit.

`PINNED` = the directory name appears literally in tracked source, so
something depends on it. **Never delete a PINNED run.** `incomplete` = fewer
patient sub-directories than the largest run in the same analysis, i.e. an
aborted pass. `unreferenced` means only that no code names it - confirm
against this table before pruning anything.

`journaled` = named in `docs/experiments/` but not in code. Still prunable —
an entry records that a question was asked, not that paper output depends on
the run. Update the entry to record the deletion *before* deleting.

`derived` and `per-patient` are **not runs** and must not be read as aborted
passes: `derived` is a run's own output subdirectory (`figures/`,
`source_data/`, `report/`), and `per-patient` is the pre-run-directory
`<root>/<PATIENT>/` layout that `cross_task_*` used before 2026-07-30 and
that `label_generation/` still uses for atlas provenance.

A name is matched two ways: as a timestamped run id, and - since 2026-08-10 -
as a whole-token directory literal. Without the second, any directory whose
name has no date in it read `unreferenced` however much code named it;
`original_KRR_l2_50ep` (13.5 GB, read by a notebook) and `balance_none` (read
by a paper pipeline) both did, and the first was staged for deletion.
