# Data conventions — identifiers, indexing, units, naming, raw vs derived

Routed from `AGENTS.md`. The formats an agent cannot infer from reading one file. Each rule
names the artifact that owns it; go there before restating anything here.

## Participant identifiers — two, and only one may ship

| Identifier | Example | Where it may appear |
|---|---|---|
| initials | `AA`, `WBH` | data pickles, `results/` paths, code, this directory |
| `display_id` | `NUEx041` | **everything that ships** — figures, captions, tracked source data |

`figures_for_paper/participants.json` is the single source of truth for the mapping, and
also fixes each participant's plotting colour, which must be identical in every panel and
legend. Resolve it with `display_id()` / `assign_colors()` from `paper_common`; never
hard-code a mapping or a palette in a figure script. `figures_for_paper/README.md` §1 owns
these rules.

Cohort: 12 participants (2 ECoG, 10 sEEG), of whom 6 have both tasks — AA AZ DR LH RB WBH.

### The glob trap

Participant discovery over `data/{PAT}/` must not assume a uniform filename. All 12 have an
ROI atlas, but AA's is `AA_channels.pkl` while the others follow
`{PAT}_picture_naming_channels.pkl`. A glob of `*_picture_naming_channels.pkl` silently
drops AA — silently, because the result is a 11-participant run that looks complete. Prefer
the picture-naming file where both exist; ROI information is task-invariant.

## Run ids

Format: `YYYY-MM-DD_HH-MM-SS` followed by a free-form config slug (task, warp/align flags,
model, loss, epochs). `utils/audit_runs.py` holds the pattern.

- **Never type a run id into a module.** They are pinned in `utils/config.py`; import from
  there and keep a per-invocation CLI flag for one-off overrides.
- **Keep each id on one source line** — see `docs/agent-context/change-protocol.md` for why
  a wrapped id silently unpins a run.
- Which runs are safe to touch is `docs/results_index.md`, regenerated by
  `python -m utils.audit_runs --write`. Consult it before quoting or deleting anything.

## Indexing and feature layout

- **Feature columns:** the column for channel `c` at history bin `k` is
  `c + k * n_channels`. Reshaping to `(n_bins_history, n_channels)` is therefore
  C-order-correct; the transpose is a silent alignment bug, not an error.
- **Channel names → electrode → `primary_roi`** is its own resolution chain with its own
  per-patient exceptions and one fixed bug worth knowing about:
  `docs/agent-context/channel-and-roi-naming.md` owns it. Do not reconstruct a channel name
  from a post-exclusion column index.
- Never infer an axis's meaning from its length. Two axes of equal size are the most
  common way an alignment error survives to a plausible-looking result.

## Units

Mixed by convention, and the mix is load-bearing — read the suffix, do not assume:

| Quantity | Unit | Seen as |
|---|---|---|
| alignment window | **seconds** | `align_back_sec`, `align_forward_sec` |
| bin size | **milliseconds** | `bin_size_ms` |
| history | count of bins | `n_bins_history` |
| high-gamma band | Hz | 70–200 Hz broadband |
| warp target | **seconds** | `auditory_warp_target_sec` |

These names are the manifest keys written into each run's `meta.json`; a value read from a
manifest carries its unit in its key.

## File and directory naming

- **Results:** one root, `results/<analysis>/<run_id>/`, always via
  `utils.paths.results_dir("<analysis>")` — never a hand-composed or relative path. The
  `<analysis>` key matches either the analysis's code folder or its `figures_for_paper/`
  folder, so a reader can move between code, results, and figures by name alone.
  `utils/paths.py` explains what happens when this is ignored.
- **Figures for the paper:** `.png` **and** `.pdf`, both every time, numbered by panel
  order — `00_*` for the combined figure or legend, then `01_*`, `02_*`, …
- **Source data:** the arrays actually plotted, plus any reusable cache, go to
  `{analysis}/source_data/*.csv` and nowhere else. These are tracked, including the
  `cache_*` files. A per-participant CSV carries `display_id` as its first column.
  `figures_for_paper/README.md` §2 owns the layout.
- The directory name `results` cannot be changed; `.gitignore` excludes `*results`, so
  renaming the tree would stage the entire 169 GB of output. `docs/repo_layout.md` covers
  this and the OneDrive placeholder behaviour that makes a `cp` far more expensive than
  an `mv`.

## Raw versus derived

- Everything under `data/` — raw signals and acquisition files — is **read-only**.
- Derived output is rewritable, and belongs under `results/` or a figure's `source_data/`.
  Never write a derived output into a raw-data directory.
- Every figure must be reproducible from its own `source_data/` alone, in a clean checkout.
- A run made on a dirty working tree is flagged `git_dirty` in its manifest and its
  configuration cannot be reconstructed from the commit — treat it as provenance-incomplete.
  `docs/agent-context/scientific-integrity.md` owns the provenance rules.
